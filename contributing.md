# Участие в разработке

Инструкции для форка [ArtimTikhonov/bruno-clean](https://github.com/ArtimTikhonov/bruno-clean).
Ошибки этой сборки сообщайте в [Issues форка](https://github.com/ArtimTikhonov/bruno-clean/issues/new/choose).
Не направляйте обращения о специфичных изменениях форка разработчикам оригинального Bruno.

## Начало работы

Используйте Node.js из [.nvmrc](.nvmrc) и npm workspaces.
Подготовка окружения и упаковка описаны в [building.md](docs/fork/building.md).

```bash
git clone https://github.com/ArtimTikhonov/bruno-clean.git
cd bruno-clean
npm run setup
npm run dev
```

`setup` удаляет зависимости перед переустановкой. Для воспроизводимой установки
используйте `npm ci --legacy-peer-deps`.

## Как предложить изменение

1. Создайте ветку от `main`, например `fix/settings-layout` или `feat/localization`.
2. Ограничьте PR одной понятной задачей. Сохраняйте стиль окружающего кода.
3. Опишите результат и проверку; приложите скриншот для заметных изменений интерфейса.
4. Обновите `[Unreleased]` в [CHANGELOG.md](CHANGELOG.md), если меняется поведение для пользователя.
5. Запустите относящиеся к изменению проверки. Не включайте реальные токены, пароли и коллекции с секретами.

Используйте Conventional Commits: `feat: ...`, `fix: ...`, `docs: ...`, `chore: ...`, `test: ...`.
Несовместимые изменения отмечайте `!` и объясняйте миграцию в описании.

## Особенности форка

- Не возвращайте рекламу, удалённую ленту объявлений и ИИ-функции без отдельного обсуждения.
- Переводите только интерфейс: не меняйте значения запросов, URL, код, имена переменных и идентификаторы.
- Сохраняйте подстановки `{{valueN}}` и формы множественного числа.
- Новые термины добавляйте в `ui.ru-it.json`, если они должны оставаться английскими в соответствующем режиме.
- Не удаляйте технические защитные ограничения под видом отключения тарифных лимитов.
- Сохраняйте исходные лицензии и авторство.

## Проверки

```bash
npm run version:check
npm run test:fork
npm run lint -- path/to/changed-file.js
npm run build:web
```

`test:fork` проверяет логику версий, локализацию и изоляцию объявлений.
Сборки Windows/Linux и проверки запуска выполняет GitHub Actions. Проверяйте также
изменённую функцию; общие upstream-тесты запускайте по области изменения.

## Версии и upstream

Обновляйте upstream отдельным PR: изучите изменения, проверьте конфликты,
локализацию, отсутствие возвращённых ИИ-функций и рекламы, совместимость коллекций.
Не переписывайте опубликованные теги и историю `main`.

Номер выпуска меняется при подготовке релиза по [правилам версионирования](docs/fork/versioning.md).
Общие пакеты монорепозитория сохраняют собственные upstream-версии.
