# Версии и выпуск релизов

## Политика

С 2.1.0 у форка собственное семантическое версионирование **MAJOR.MINOR.PATCH**.
Номера не обозначают версию официального Bruno.

| Изменение | Номер | Пример |
| --- | --- | --- |
| Исправление без намеренного нарушения совместимости | PATCH | `2.1.0 → 2.1.1` |
| Новая совместимая возможность | MINOR | `2.1.0 → 2.2.0` |
| Несовместимое изменение, требующее миграции | MAJOR | `2.1.0 → 3.0.0` |

Поддерживаются предварительные версии: `2.2.0-beta.1`, `2.2.0-rc.1`.
Метаданные сборки `+...` в номерах релизов не используются: каждому выпуску нужен однозначный тег.
Несовместимые изменения и миграцию описывайте в CHANGELOG.

Версия согласована между:

- корневым `package.json`;
- `packages/bruno-app/package.json`;
- `packages/bruno-electron/package.json`;
- соответствующими записями `package-lock.json`;
- разделом корневого `CHANGELOG.md`;
- Git-тегом `vX.Y.Z` (либо `vX.Y.Z-beta.N`), версией приложения и именами файлов релиза.

Общие библиотеки сохраняют собственные версии. Не выполняйте массовое
`npm version --workspaces`: это может изменить upstream-пакеты и зависимости между ними.

## Подготовка

1. Перенесите готовые изменения из `[Unreleased]` в `## [X.Y.Z] - YYYY-MM-DD` в `CHANGELOG.md`.
2. Добавьте ссылку на будущий релиз внизу CHANGELOG и обновите ссылку `[Unreleased]`.
3. Выполните `npm run version:set -- X.Y.Z`. Команда синхронизирует desktop-манифесты и lockfile,
   не устанавливает зависимости и не создаёт коммит или тег. Понижение версии запрещено.
4. Обновите заметки в `packages/bruno-app/src/components/ChangelogTab/CHANGELOG*.md`.
5. Запустите `npm run version:check` и `npm run test:fork`, проверьте diff.
6. Создайте коммит, например `chore(release): prepare v2.1.1`, и отправьте ветку в GitHub.

Посмотреть будущий текст GitHub-релиза:

```bash
node scripts/version.cjs notes
```

## Публикация

После проверки релизного коммита создайте аннотированный тег на этом же коммите:

```bash
git tag -a v2.1.1 -m "Bruno 2.1.1"
git push origin v2.1.1
```

Workflow сверяет тег и версии, собирает Windows x64 и Linux x64, проверяет запуск
и только затем создаёт GitHub Release. Текст берётся из раздела CHANGELOG.
Предварительные версии отмечаются **Pre-release** и не назначаются Latest.

Коммиты в `main` запускают CI без публичного релиза. Ручной запуск workflow тоже создаёт
только артефакты CI. Для публикации нужен push тега версии.

Проверки выпуска:

- версии манифестов, lockfile и тега совпадают;
- в CHANGELOG есть запись с датой;
- переводы, подстановки и пользовательские значения проходят проверки;
- обе платформы собираются и проходят запуск; на Windows проверяется установка;
- русский, русский с английскими терминами и English работают после перезапуска;
- релиз содержит оба установочных файла и `SHA256SUMS.txt`.

## Уже опубликованные версии

Не меняйте опубликованный тег или файлы под тем же номером.
Исправления выпускайте следующей PATCH-версией. Если CI упал до публикации релиза,
исправьте причину; при изменении исходников используйте новый номер и новый тег.
Повторный запуск допустим для сбоя инфраструктуры на неизменном коммите до публикации.

`clean-build-N` — исторические сборки с прежней нумерацией. Они сохраняются без переписывания;
их номер не является SemVer-версией приложения.
